# Что необходимо сделать

1. Человек уже добавил необходимые изменения в git stage, прочитай изменения с помощью команды:

```
git diff --cached
```

2. Выполни анализ полученных изменений, ответь для себя на вопрос зачем эти изменения были сделаны.
3. Проверь, не нарушена ли обратная совместимость, если не уверен, спроси у человека. Если совместимость не нарушена, не отражай это в сообщениях. Если нарушена — используй BREAKING CHANGE.
4. Следуй стилю Commitizen, но на русском языке используй безличные краткие причастия (страдательный залог) в прошедшем времени. Пример правильного формата: refactor(scope): заменены X на Y. Неправильно: refactor(scope): заменил X на Y. Сделай commit с помощью команды ниже:

```
git commit -m "fix(scope): краткое описание изменений"
```

# Дополнительные требования

1. В ответе человеку напиши что работа выполнена, не дублируй информацию которую ты уже сделал.
2. При наличии двух и более логически самостоятельных изменений в одном коммите оформляй их в виде маркированного списка. Каждый пункт — одно законченное изменение, начинающееся с краткого страдательного причастия. Между заголовком и списком обязательна пустая строка, каждый пункт начинается с маркера списка (дефис - или звёздочка *). Запрещено писать перечисление сплошным абзацем без маркеров.

**Пример 1**
Вход: исправлена опечатка в имени функции записи CRC, добавлены проверки валидности параметров в конструкторе
```bash
fix(radio_message_parser): исправлено имя функции RPM_WriteCrcInMessageTail → RMP_WriteCrcInMessageTail

- Исправлена опечатка в имени функции записи CRC во всех местах использования.
- Добавлены проверки валидности параметров в конструкторе RMP_Ctor.
- Исправлено сравнение счётчика прочитанных байт в RMP_FindFirstByte.
- Удалены неиспользуемые переменные и платформенно-зависимые заголовки.
- Расширено покрытие unit-тестами: граничные случаи конструктора,
  обработка пустого буфера, разделённые сообщения, мусор между сообщениями,
  переполнение буфера, порог чтения, ложный старт.
```

**Пример 2**
Вход: добавлен метод фильтрации сообщений по адресу назначения
```bash
feat(radio_message_parser): добавлена фильтрация сообщений по адресу назначения

- Реализован метод RMP_FilterByAddress для отбора сообщений.
- Обновлены публичные заголовки модуля.
```

**Контр-индикатор (что делать НЕ надо):**

```bash
...заголовок...

Исправлена опечатка... Добавлены проверки... Исправлено сравнение...
Удалены неиспользуемые... Расширено покрытие...
```
