# Detroit School + Catch2 v3 + FakeIt

Классическое unit-тестирование по Kent Beck: тестируем **поведение через публичный API**, реальные объекты-коллабораторы тестируем вместе, моки — только на границах системы.

## Принципы (детройтская школа)

1. **Тестируйте поведение, не реализацию.** Тест знает только публичный интерфейс SUT (System Under Test, иногда расшифровывают как Subject Under Test) . Переименование приватных членов, изменение внутренней структуры — тесты не должны ломаться.
2. **Не мокайте внутренние коллабораторы.** Если `order_service` использует `price_calculator` — тестируйте оба вместе с реальным `price_calculator`. Соединяйте объекты «в сборе», как в проде.
3. **Моки — только на границах системы**: сеть, БД, файловая система, системные часы, random, внешние API. Именно там, где детерминизм невозможен без подмены.
4. **Минимум абстракций ради тестов.** Не создавайте интерфейс `i_price_calculator` с единственной реализацией только чтобы замокать его в тесте. Интерфейсы выносятся только для настоящих границ.
5. **Несколько крупных поведенческих тестов** лучше множества мелких изолированных. Изоляция теста через моки внутренних объектов = тест реализации.
6. **Проверяем результат (состояние/возврат/исключение), а не взаимодействия.** Verify на вызовы допустим только на границах (например, «пакет отправлен в сокет»).

Симптомы нарушения: тесты падают при рефакторинге без изменения поведения; тест знает имена приватных методов; класс появился исключительно «для мока».

## Шаблон проектирования под тестируемость

- Зависимости границ — через конструктор (constructor injection), храним как ссылки/unique_ptr: `clock&`, `http_client&`, `repository&`.
- Бизнес-логика принимает конкретные типы коллабораторов (не интерфейсы), собирается «в сборе» в тесте.
- Детерминизм: время, random, UUID — за границей `clock`, `random_gen`.

## Чек-лист перед сдачей теста

- [ ] Тест знает только публичный API; нет обращений к приватным членам / дружественному доступу без крайней нужды
- [ ] Внутренние коллабораторы — реальные объекты, собранные вместе со SUT
- [ ] Моков нет, кроме границ (сеть/БД/ФС/часы/random)
- [ ] Assert проверяет результат, а не вызовы внутренних методов
- [ ] Имя теста — описание поведения: `TEST_CASE("rejects expired token")`
- [ ] Тест детерминирован: нет sleep, настоящего времени, сети, порядка по указателям/addresses
- [ ] Тест устойчив: падение сообщает, ЧТО сломалось (REQUIRE, CAPTURE вместо голых CHECK в критичных местах)
