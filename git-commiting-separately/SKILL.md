# Анализ изменений

Необходимо промести анализ незафиксированных изменений с помощью `git diff`.
Изменения необходимо сгруппировать по библиотекам, затем по областям изменений так, чтобы каждый из созданных коммитов можно откатить, при необходимости, в будущем с помощью git revert без поломок сборки, тестов и функциональности приложения.

# Добавление изменений в stage

После анализа первая группа изменений добавляется в git stage, сообщение фиксации формируется с помощью skill `git-committing-russian`

# Повторить для следующей группы изменений шаг "Добавление изменений в stage"

Если в git diff еще остались изменения, то повторить шаг "Добавление изменений в stage".
